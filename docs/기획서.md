## 1. 배경과 목표

### 1.1 왜 만드는가
- Yousician처럼 "치면 듣고 채점해 주는" 앱이 초보에게 잘 맞아 보이지만 구독료가 부담이다. 핵심 경험만 골라 직접 만든다.
- 독학의 약점은 세 가지다. 틀려도 알려 줄 사람이 없고, 연습 순서를 스스로 정해야 하고, 막히는 구간(특히 F 코드)에서 그만두기 쉽다 [K1][K2]. 앱이 이 세 가지를 구조로 메운다.

### 1.2 성공 기준
1. 본인이 실제 기타로 매일 켜서 쓴다(연속 연습일로 확인).
2. 단음 판정이 조용한 방에서 믿을 만하다(맞게 쳤는데 틀렸다고 나오는 일이 드물다).
3. 16주 과정(0~10단계)을 끝까지 따라갈 수 있다.

### 1.3 하지 않는 것
- 영상 강의 제작. 자세와 손 모양은 그림과 짧은 글로 설명하고, 필요한 곳에는 무료 영상 강의 링크를 붙인다.
- 최신 가요 음원과 악보 수록(저작권). 11장 참고.
- 로그인, 서버, 결제.
- 일렉기타, 베이스, 우쿨렐레(구조는 막지 않되 이번 범위 밖). 통기타(쇠줄)는 튜닝과 음이 같아 앱은 그대로 쓸 수 있지만 설명은 클래식 기타 기준으로 쓴다.

## 2. 참고 앱 분석

### 2.1 Yousician
- 구조: 학습 경로를 "미션" 단위로 나누고, 미션마다 곡·영상 설명·연습기를 묶는다. 연주 레벨은 10단계이고 주제는 멜로디·리프·리드 / 코드와 리듬 / 지식(이론, 5단계)으로 갈린다. 경로는 잠겨 있지 않아 원하는 미션으로 건너뛸 수 있다 [Y1].
- 강점: 마이크로 듣고 실시간으로 맞았는지 알려 준다. 곡의 템포를 늦추고 마디를 반복해 연습할 수 있다는 점을 사용자들이 높이 평가한다 [Y3][Y4].
- 가격(미국 기준, 2026-11-02 확인 자료): Premium 월 14.99달러 또는 연 89.99달러(악기 1종), Premium+ 월 29.99달러 또는 연 139.99달러(전 악기). 지역마다 다르다 [Y2].
- 무료 사용: 하루 사용 시간이 짧게 제한되고, 구독해야 제한이 풀린다 [Y4]. 스토어 리뷰에는 첫 레슨 뒤로 대부분이 잠겨 있다는 불만이 보인다 [Y5].
- 불만: 시끄러운 방이나 튜닝이 틀어진 기타에서 맞게 쳐도 틀렸다고 나온다. 점수를 좇다 보면 서두르고 딱딱하게 치게 된다. 이론과 주법 설명이 얕다 [Y4]. 요금제가 바뀌면서 치던 곡이 잠겼다는 사례도 있다 [Y5].

### 2.2 다른 서비스에서 배울 점
- JustinGuitar: 웹사이트 초급 과정이 무료다. Grade 1 한 과정으로 오픈 코드 8개와 기본 스트로크를 끝낸다. 순서는 A·D → E → 마이너 코드와 업 스트로크 → 메트로놈과 Dm → C → G다 [J1][J2]. 연주를 듣고 판정하는 기능은 없다는 평가가 있다 [J3].
- Simply Guitar: 첫 주 경험이 단순하다. 악기 소개 → 튜닝 → 음 → 코드 → 짧은 연주 과제 순서로 가고, 그 뒤에 멜로디 길과 코드 길로 갈린다 [S1].
- Fender Play: 경로 → 레벨 → 코스 → 활동의 계단 구조이고, 초반 곡은 쉽게 편곡해 준다 [F1].

### 2.3 우리 앱에 가져올 핵심 5가지
1. 마이크 실시간 판정(단음 먼저, 코드는 그다음).
2. 흘러가는 TAB 화면 + 템포 조절 + 구간 반복.
3. 단계별 길. 잠그지 않고 건너뛸 수 있게 한다.
4. 가벼운 보상: 별, 연속 연습일. 점수보다 "깨끗한 소리"와 "꾸준함"을 칭찬한다.
5. 내장 튜너. 튜닝이 틀어지면 판정이 틀리므로 연습을 시작할 때마다 튜닝을 확인하게 한다.

### 2.4 다르게 가는 점
- 시간 제한과 잠금이 없다.
- 전부 한국어이고, 용어는 국내 교재에서 쓰는 말을 따른다.
- "한 줄씩 점검"으로 코드에서 어느 줄이 안 울리는지 알려 준다(3장 실험 결과로 정한 기능).
- 가입·설치가 없고 기록은 기기에만 남는다.

## 3. 기술 타당성

### 3.1 조사 결과
- 브라우저만으로 마이크 소리를 받아 실시간으로 음 높이를 구할 수 있다(getUserMedia + Web Audio API). 공개된 구현이 여럿 있다 [T1][T2][T3].
- FFT 스펙트럼만으로는 낮은 음을 못 가른다. 48kHz, 2048 창에서 주파수 한 칸이 23.4Hz인데 6번줄 근처 반음 간격(E2 82.41Hz, F2 87.31Hz)은 4.9Hz다. 그래서 시간 영역 방식(자기상관, YIN, McLeod)을 쓴다 [T3].
- 기타는 배음이 강해 단순 자기상관은 옥타브를 헷갈린다(110Hz와 440Hz 사이를 오간 사례). 보정이 들어간 방식이 필요하다 [T4].
- 마이크는 보안 연결(HTTPS 또는 localhost)에서만 열리고, 사용자가 버튼을 누른 뒤에만 시작할 수 있다. iOS에서는 AudioContext도 사용자 동작 안에서 시작해야 한다 [T5][T6].
- 통화용 소리 보정(echoCancellation, noiseSuppression, autoGainControl)은 악기 소리를 망가뜨리므로 셋 다 꺼야 한다 [T7].
- 코드 인식의 표준 방법은 크로마(12음별 에너지)를 구해 코드 템플릿과 비교하는 것이다 [T8][T9]. 실제 마이크 녹음에서 최신 딥러닝 모델의 코드 인식 정확도가 80~90% 수준이라는 연구가 있다 [T10]. 100%를 기대하면 안 된다.

### 3.2 직접 실험(합성 신호)
`node spike/feasibility.mjs` 로 다시 돌릴 수 있다. 기타 소리를 흉내 낸 합성음(배음 12개, 약한 비조화성, 감쇠, 잡음)에 McLeod 방식 검출기를 직접 구현해 시험했다.

단음(E2~E5, 37개 음 x 5회, 48kHz):

| 분석 창 | 깨끗한 소리 | 기본음 약함(휴대폰 마이크 흉내) | 시끄러운 방 | 기본음 약함 + 시끄러움 |
|---|---|---|---|---|
| 1024샘플(21ms) | 91.9% (E2·F2·F#2 불가) | 91.9% | 93.5% | 89.2% |
| 2048샘플(43ms) | 100% | 100% | 100% | 96.8% |
| 4096샘플(85ms) | 100% | 100% | 100% | 98.4% |

- 맞힌 경우의 오차는 깨끗한 조건에서 5센트 이내였다(튜너로 쓸 만한 수준).
- 시끄러운 조건에서는 ±10센트 정밀도가 73~85%로 떨어진다. 튜너는 여러 프레임의 중앙값을 써야 한다.

코드(오픈 코드 8개 + Fmaj7 + F, 코드당 40회, 창 171ms):

| 템플릿 | 깨끗한 소리 | 기본음 약함 + 시끄러움 |
|---|---|---|
| 구성음만 표시한 이진 템플릿 | 96.0% | 95.5% |
| 실제 운지를 반영한 템플릿 | 97.8% | 96.0% |

- 가장 많이 틀린 것은 Fmaj7을 Am으로 본 경우다(두 코드는 음 하나 차이).
- 한 줄이 안 울리는 실수는 코드 점수로 잘 드러나지 않았다. C 코드에서 4번줄이 죽어도 점수가 0.960 → 0.958로 거의 그대로였다.

### 3.3 결론

| 기능 | 가능성 | 근거와 조건 |
|---|---|---|
| 튜너 | 높음 | 85ms 창 + 중앙값. 공개 구현 다수 |
| 단음 판정 | 높음 | 43ms 창으로 기타 전 음역 구분. 조용한 방이 조건 |
| 박자 판정 | 중간 | 기기마다 마이크 지연이 달라 지연 보정 화면이 필요 |
| 코드 판정("이 코드가 맞나" 확인) | 중간 | 합성 기준 96% 안팎. 비슷한 코드 쌍은 구분음 확인을 따로 넣어야 함 |
| 코드에서 안 울리는 줄 찾기 | 코드 소리만으로는 낮음 | 한 줄씩 치게 하고 단음 검출로 확인하면 높음 |
| 자세·손 모양 교정 | 불가 | 소리만 듣는다. 그림과 점검표로 대신한다 |

합성 신호는 실제 녹음보다 깨끗하다. 그래서 1단계의 완료 기준을 "본인 기타로 실제 확인"으로 잡고, 그때 녹음한 소리를 시험 자료로 남긴다.

## 4. 핵심 경험

```
오늘의 연습(15분)
  1) 튜닝 확인 1분
  2) 복습 1개: 어제 틀린 구간
  3) 새 레슨 1개: 설명 → 시범 소리 듣기 → 따라 치기(판정) → 별
  4) 1분 코드 전환 챌린지(코드 단계부터)
  5) 곡 한 번 치기 → 기록 저장, 연속 연습일 +1
```

판정 연습에는 두 가지 방식을 둔다.
- 기다려 주기: 맞는 음을 칠 때까지 악보가 멈춰 기다린다. 박자 부담 없이 음을 찾는 연습이다. 처음에는 이것만 쓴다.
- 박자 맞추기: 악보가 흘러가고 제때 쳤는지까지 본다. 템포는 50~100%로 늦출 수 있다.

## 5. 학습 단계(커리큘럼)

순서를 정한 근거: 손가락을 적게 쓰는 코드부터(Em·Am → C·G → D·E) [K1], 코드를 따로 외우기보다 곡의 진행 순서대로 전환을 연습하고 [K3], 전환 횟수를 숫자로 기록하고 [K1], F 코드는 Fmaj7과 작은 F를 거쳐 늦게 만난다 [K1][K2][K4]. 마이크 판정이 가장 믿을 만한 단음부터 시작해 판정 경험에 익숙해진 뒤 코드로 넘어간다(3장). 목표가 반주와 연주 둘 다이므로 반주 길(3~6, 8~9단계)과 연주 길(2, 7, 10단계)을 번갈아 놓았다. 클래식 기타라서 피크 대신 오른손 손가락으로 치는 법을 0단계부터 쓴다.

| 단계 | 주제 | 배우는 것 | 연습 과제 | 판정 방식 | 기간(안) |
|---|---|---|---|---|---|
| 0 | 준비 | 기타 각 부분 이름, 앉는 자세, 오른손 손가락 이름(p 엄지, i 검지, m 중지, a 약지), 튜닝 | 6줄 튜닝하기 | 튜너(±6센트) | 1~2일 |
| 1 | 줄과 프렛 | 줄 번호와 개방현 음(E A D G B E), 프렛, TAB 읽기 | 부르는 개방현 치기(4~6번줄은 엄지, 1~3번줄은 검지·중지) | 단음, 기다려 주기 | 3~4일 |
| 2 | 단음 멜로디 | 1~3번줄 1~3프렛, 왼손 손가락 번호, 검지·중지 번갈아 치기 | 쉬운 멜로디 3곡 | 단음, 기다려 주기 → 박자 | 1~2주 |
| 3 | 첫 코드 | Em, Am. 코드표 읽기, 엄지로 쓸어 내리기 4박 | 한 줄씩 점검, Em↔Am 전환 | 한 줄 점검 + 코드 확인 | 1주 |
| 4 | 코드 넓히기 1 | C, G, D | 1분 전환 챌린지(C↔Am, G↔Em, G↔D, C↔G) | 코드 확인 + 전환 횟수 | 2주 |
| 5 | 스트로크와 박자 | 엄지 다운, 검지 다운·업, 8비트, 칼립소(↓ ↓↑ ↑↓↑), 메트로놈 | 한 코드로 리듬, 두 코드로 리듬 | 스트로크 시점(박자) | 1~2주 |
| 6 | 첫 곡 반주 | G-Em-C-D, C-Am-Fmaj7-G 진행 | 곡 2~3개 끝까지 | 코드 확인 + 박자 | 2주 |
| 7 | 아르페지오 | 엄지 베이스 + 검지·중지·약지(p-i-m-a), 기본 패턴 2가지 | 코드 진행을 아르페지오로 | 단음 순서 | 2주 |
| 8 | 코드 넓히기 2 | E, A, Dm, 세븐스(G7, D7, A7, E7), 카포 | 새 진행으로 전환 챌린지 | 코드 확인 | 2주 |
| 9 | F 코드 다리 | Fmaj7 → 작은 F(1·2번줄 바) → 바레 F | C↔F, Am↔F, G↔F 전환, 한 줄 점검 | 한 줄 점검 + 코드 확인 | 2~4주 |
| 10 | 멜로디와 베이스 함께 | 엄지로 베이스를 치면서 멜로디 얹기, 쉬운 독주곡 | 독주곡 1~2곡 | 단음 순서 + 박자. 두 음을 함께 칠 때는 코드 확인 방식을 응용(정확도는 그때 측정) | 3~4주 |

- 기간은 하루 15~20분을 기준으로 한 추정이다. 독학 자료들은 매일 20~30분씩 3개월이면 오픈 코드 6~8개와 쉬운 곡 반주, F 코드를 겨우 잡는 수준을 목표로 본다 [K1].
- 단계는 잠그지 않는다. 다만 다음 단계로 넘어갈 "권장 기준"(예: 전환 1분 30회)을 보여 준다.
- 모든 단계에 "손끝이 아프면" 안내를 넣는다. 몰아서 오래 하기보다 매일 짧게 하는 쪽이 낫다는 점을 알려 준다 [K2][K5].

## 7. 판정 설계

### 7.1 단음
- 마이크 설정: echoCancellation, noiseSuppression, autoGainControl 모두 끔 [T7].
- 검출: McLeod 방식(정규화 제곱차 함수에서 첫 번째 유력 봉우리 선택, 포물선 보간). 연습용 창 2048샘플, 튜너용 4096샘플.
- 맞음 조건: 목표 음에서 ±50센트 안, 선명도 기준 이상, 연속 2프레임 이상 유지.
- 튜너: 최근 5프레임 중앙값을 표시하고 ±5센트 안이면 "맞음".
- 소리가 작거나 선명도가 낮으면 "판정 보류"로 두고 틀렸다고 하지 않는다. 맞게 쳤는데 틀렸다고 나오는 것이 가장 큰 불만 요인이기 때문이다 [Y4].

### 7.2 박자
- 음의 시작(에너지가 갑자기 커지는 지점)을 잡아 악보 시각과 비교한다.
- 허용 범위(안): 정확 ±80ms, 괜찮음 ±160ms. 실제 기기에서 써 보고 조정한다.
- 지연 보정: 메트로놈에 맞춰 줄을 8번 치게 하고 평균 어긋남을 기기별로 저장한다.
- 블루투스 이어폰과 마이크는 지연이 크므로 판정 중에는 쓰지 않도록 안내한다.
- 스피커에서 나오는 반주와 메트로놈 소리가 마이크로 다시 들어가면 판정을 방해한다. 판정 중에는 시범 소리를 끄고 화면 메트로놈을 기본으로 한다. 유선 이어폰을 쓰면 소리를 켤 수 있다.

### 7.3 코드
무슨 코드인지 알아맞히지 않고, 지금 쳐야 하는 코드가 맞는지만 확인한다. 문제가 훨씬 쉬워진다.
1. 스트로크 시작을 잡고 0.15초 뒤부터 171ms 구간을 분석한다.
2. 크로마를 구해 기대 코드의 운지 반영 템플릿과 비교한다.
3. 헷갈리기 쉬운 이웃 코드(Em↔E, Am↔A, Dm↔D, Fmaj7↔Am↔F, C↔Am)와도 비교해, 기대 코드가 가장 높고 차이가 충분하면 통과시킨다.
4. 이웃 코드 쪽이 더 높으면 구분음을 짚어 준다. 예: "Am처럼 들려요. 4번줄 3프렛(파) 소리를 확인해 보세요."
5. 가장 낮은 음(근음)을 저음 대역 단음 검출로 한 번 더 확인한다.

### 7.4 한 줄씩 점검
- 코드를 잡은 채 치는 줄을 화면이 하나씩 가리키고, 단음 검출로 줄마다 기대 음이 맑게 나는지 본다.
- 결과는 맑음 / 먹먹함(선명도 낮음, 금방 사라짐) / 다른 음(잘못 누름) / 쳐야 하지 않는 줄을 침으로 나눈다.
- 강사들이 권하는 "코드를 잡고 한 줄씩 쳐 보기"를 그대로 옮긴 것이다 [K6].

## 10. 기술 구성

- 언어와 도구: HTML + CSS + 순수 JavaScript. 프레임워크와 외부 라이브러리 없이 시작한다.
- 결과물: 파일 하나로 된 `index.html`. 소스는 `src/`에 기능별로 나누고, 의존성 없는 빌드 스크립트로 한 파일로 합친다.
- 소리 입력: getUserMedia → AudioContext → AnalyserNode에서 시간 영역 데이터를 읽어 검출. 필요해지면 AudioWorklet으로 옮긴다.
- 소리 출력: Web Audio 합성음(줄 튕기는 소리 흉내, 메트로놈). 음원 파일을 쓰지 않는다.
- 그리기: 흘러가는 TAB은 Canvas, 코드표와 지판 그림은 SVG.
- 저장: localStorage. 나중에 파일로 내보내기·가져오기.
- 판정 엔진(피치 검출, 음 이름 변환, 크로마, 채점)은 화면과 분리한 순수 함수로 만들어 node에서 시험한다.
- 직접 구현하는 이유: 필요한 알고리즘이 100줄 안팎이고(이번 실험에서 구현함) 파일 하나로 유지하기 쉽다.

## 11. 곡과 저작권

- 수록 원칙: 저작권 보호 기간이 끝난 전래 곡·고전 곡의 선율과, 이 앱을 위해 직접 만든 연습곡만 싣는다. 가사는 싣지 않는다.
- 후보(수록 전에 곡마다 다시 확인): 작은 별, 나비야, 환희의 송가, 아리랑, 오 수재너, 어메이징 그레이스, 메리의 어린 양, 그린슬리브스. 독주곡 후보는 로망스(작자 미상) 앞부분과 위 선율의 쉬운 독주 편곡.
- 최신 가요는 싣지 않는다. 대신 "내 곡 만들기"로 사용자가 코드 진행을 직접 입력해 개인 연습용으로 쓴다.
- 흔한 코드 진행(G-Em-C-D, C-Am-F-G, C-G-Am-F)으로 만든 자체 연습곡을 단계마다 넣는다.

| 기기마다 지연이 다름 | 박자 판정 불공정 | 지연 보정 화면, 처음에는 기다려 주기 방식만 |
| 스피커 소리가 마이크로 들어감 | 오판정 | 판정 중 소리 끔, 화면 메트로놈, 유선 이어폰 안내 |
| 코드 판정이 비슷한 코드를 헷갈림 | 잘못된 칭찬·지적 | 기대 코드 확인 방식 + 구분음 확인 + 한 줄 점검 |
| 자세·손 모양을 볼 수 없음 | 나쁜 습관 | 그림, 점검표, 무료 영상 링크 |
| 내용(레슨 글·악보) 분량이 많음 | 일정 지연 | 엔진을 먼저 끝내고 레슨은 데이터로 분리해 조금씩 추가 |
| 곡 저작권 | 공개 시 문제 | 11장 원칙. 공개 배포 전 곡별 재확인 |

## 19. 2~5단계에서 만든 것 (2026-11-12)

- 음 추적기: 줄을 튕긴 순간과 친 음을 잡는다. 쳐야 할 음을 알고 있을 때는 "그 음이 들리는가"를 먼저 확인해서, 앞서 친 줄이 계속 울려도(아르페지오, 멜로디) 새 음을 구분한다. 크게 울리는 베이스 위에 살짝 친 음도 직전보다 또렷해졌는지로 잡는다.
- 채점: 기다려 주기(맞는 음까지 기다림, 방금 맞힌 음이 다시 들린 것은 틀림으로 세지 않음), 박자 맞추기(정확 ±80ms, 괜찮음 ±160ms, 기기 지연 보정 반영).
- 코드: 코드 15개(Em, Am, C, G, D, E, A, Dm, G7, D7, A7, E7, Fmaj7, 작은 F, F). 한 줄씩 점검(맑음, 먹먹함, 다른 음), 쓸어 친 소리로 코드 확인(헷갈리는 코드로 들리면 그 이름을 알려 줌), 1분 전환 횟수 기록, 스트로크 박자와 마디별 코드 확인.
- 레슨 39개(0~10단계), 곡: 작은 별, 메리의 어린 양, 환희의 송가, 작은 별 독주, 반주 연습곡 3개, 내 곡 만들기(코드 진행과 리듬을 직접 입력).
- 기록: 레슨별 별, 연속 연습일, 이번 주 연습한 날, 오늘 연습 시간, 오늘의 연습(튜닝 → 복습 → 새 레슨), 기록 내보내기·가져오기.
- 도구: 메트로놈, 박자 보정(화면의 원에 맞춰 8번 치면 기기 지연을 잼), 마이크 민감도.
- 시험: node 단위 시험 46개 통과. 합성한 기타 소리로 단음 멜로디, 개방현 오르내리기, 아르페지오, 스트로크(60~100BPM), 코드 10종 이상의 확인과 헷갈리는 코드 거르기, 한 줄 점검을 확인했다. 브라우저에서 합성음을 넣는 시험 모드로 모든 연습 화면이 끝까지 돌아가는 것을 확인했다.
- 한계: 두 음을 동시에 치는 독주는 아직 다루지 않는다(10단계는 베이스와 멜로디를 번갈아 치는 수준). 실제 마이크 소리는 합성음보다 지저분하므로 판정 기준은 실제 확인 뒤 조정해야 한다.

## 21. v0.6: 보정 도우미와 공통 개선 (2026-11-13)

배경: 세 앱 업데이트 기획(2026-11-13, 사용자 「추천대로 진행해요」)의 1순위. v0.5는 판정 기준을 합성음으로만 맞췄고, 실제 기타 결과를 사용자가 복사해 보내 주어야 기준을 고칠 수 있었다. v0.6은 앱이 기기에서 직접 재고 스스로 기준을 정한다.

### 21.1 보정 도우미 (도구 → 보정 도우미, 주소 `#adjust`)
- 순서: 튜닝 확인 안내 → 조용한 방 3초 → 개방현 6번줄~1번줄 3초씩 → Em, C, G 코드 3초씩. 단계마다 1.4초 준비 뒤 3초 녹음, 소리를 못 들으면 한 번 더 시킨다. 약 50초.
- 재는 것(`src/js/calibrate.js`): 방 잡음(25ms 조각 음량의 90백분위), 줄마다 최대 음량·울림 음량(튕긴 뒤 0.3~0.7초)·맞힘 비율·선명도와 기대 음 또렷함(25백분위), 코드마다 코드 점수(튕긴 뒤 0.18·0.4·0.7초의 가운데 값).
- 기준 계산과 안전 범위:

| 기준 | 기본값 | 계산 | 범위 |
|---|---|---|---|
| 소리 크기 `minRms` | 0.004 | 방 잡음 ×3 이상, 가장 작게 울린 줄 ×0.3 이하. 둘이 겹치면 기하평균 + 안내 | 0.0015~0.02 |
| 음 선명도 `minClarity` | 0.80 | 가장 흐린 줄의 선명도 −0.04, 기본값보다 높이지 않음 | 0.70~0.88 |
| 기대 음 또렷함 `minSalience` | 0.70 | 가장 낮은 줄 −0.05, 기본값보다 높이지 않음 | 0.55~0.80 |
| 코드 점수 `chordMinScore` | 0.78 | 가장 낮은 코드 −0.05, 기본값보다 높이지 않음 | 0.62~0.85 |

- 원칙: 선명도·코드 기준은 느슨하게만 푼다(까다롭게 하면 맞게 쳐도 틀렸다고 나올 위험이 더 크다). 소리 크기 기준만 오르내린다.
- 저장: `progress.settings.calib`(판 번호, 날짜, 샘플레이트, 기준값, 잰 숫자). 기록 내보내기·가져오기에 그대로 담긴다. 판 번호가 다르거나 값이 망가지면 기본값을 쓰고, 범위 밖 값은 다시 묶는다.
- 쓰는 곳: `trackerOptions`(소리 크기·선명도·기대 음 또렷함, 마이크 민감도는 보정값에 곱함: 낮게 2배, 높게 절반), 코드 확인과 반주 연습의 `verifyChord` `minScore`.
- 화면: 결과 요약(줄·코드별 「잘 들려요」 등), 기준 표(기본값과 이 기기 값), 다시 보정, 기본값으로, 결과 복사, 녹음 WAV 저장(모든 녹음을 0.5초 간격으로 이은 파일, 구간은 결과 복사에 적힘). 결과를 보낼 필요는 없다. WAV는 나중에 `tests/` 고정 시험 자료로 쓸 수 있다.
- 안내: 보정 전에는 홈 「오늘 할 것」에 「처음 한 번 · 보정 도우미」 항목, 튜너에 안내 한 줄이 나온다.

### 21.2 애매한 판정은 「다시 쳐 볼까요」
- 단음(기다려 주기): 기대 음으로 확인된 것이 아니고, 선명도가 기준 +0.05 안이거나 두 음 사이(35센트 넘게 어긋남)에 걸친 음은 `unsure`로 표시하고 틀림으로 세지 않는다.
- 코드 확인·반주: 점수가 기준 바로 아래(0.05 폭 안)면 `unsure`로 두고 시도·마디 표에 세지 않는다.

### 21.3 공통 개선
- 인터넷 없이 열기: `sw.js`(빌드가 `src/sw.template.js`로 만든다). 화면은 늘 새 판을 먼저 받고 연결이 없을 때만 저장본, 아이콘·manifest는 저장본 먼저. 판 번호는 `APP_VERSION`과 index.html 해시라서 새로 올리면 옛 저장본을 지운다. https와 localhost에서만 등록하고 파일로 열 때는 쓰지 않는다. 마이크 사용과는 무관하다.
- 밝은 화면: 설정 「화면 밝기」 자동(기기 설정 따라)·어둡게·밝게. 밝은 화면에서는 빛 번짐·빛망울·입자 질감·그림자를 빼고, 강조색을 진한 호박색 #8F5D00(밝은 바탕 대비 약 5:1)으로 바꾼다. 홈 첫 그림만 어두운 무대로 남긴다. 첫 그림 전에 head의 작은 스크립트가 밝기를 정해 깜박임을 막는다.
- 새로 생긴 것: 업데이트 뒤 홈 맨 위에 한 번 보여 주고 「확인했어요」를 누르면 사라진다. 처음 쓰는 사람에게는 보여 주지 않는다.

### 21.4 확인한 것
- node 시험: 보정 계산(깨끗한 소리면 기본값 근처, 시끄러운 방, 엉뚱한 값 묶기), 합성음 보정 효과(소리를 작게 받는 마이크에서 기본값은 개방현 6개를 하나도 못 듣고, 보정하면 6개 모두 듣는다), 저장·가져오기, 애매한 판정, sw.js 판 번호와 파일 목록.
- 브라우저: 마이크 대신 발진기 소리를 넣는 방식으로 보정 도우미를 처음부터 끝까지 진행(태블릿 가로 1180×820 어둡게, 휴대폰 세로 390×844 밝게), 작은 소리 시나리오, WAV 저장, 기본값으로 되돌리기, 홈 안내, 설정 밝기 전환, 서버를 끈 뒤 새로 고침해도 열리는 것.
- 아직 못 한 것: 실제 클래식 기타와 태블릿 마이크로 보정해 보기.
